# SoloHost Browser v10.15.0 — Media, Search Settings & AI Knowledge

## Implemented
- Default search engine selector: Bing (default), Google, DuckDuckGo, Brave Search, custom URL template. Stored in browser-profile localStorage.
- Custom search templates must be HTTP(S) and contain `{query}` or `%s`; search terms are URL-encoded. Plain text searches and selected-text search use this setting. Explicit URLs remain untouched.
- Direct links ending in common audio/video/image/PDF extensions are routed to Chromium's native viewer when available.
- Expanded CSP frame allowlist to official YouTube, TikTok, Vimeo, Spotify, Twitch and Dailymotion hosts already recognized by Bridge sanitization.
- AI adapter knowledge now derives the installed package version and capability flags at runtime; guidance covers search, media, Bridge architecture, logs, security and verification limits.

## Not guaranteed
- DRM/Widevine, codec availability, geoblocks, age/login restrictions, autoplay restrictions and site anti-bot policy are not bypassed.
- Native direct-file rendering depends on MIME type, browser support, server headers and iframe policy; some documents will download or require Open ↗.
- Custom search engines need a URL template with `{query}` or `%s`; arbitrary search forms that do not expose a URL template are not auto-discovered.
- AI knowledge is current for the installed package/capability report; it cannot magically learn future code changes until the updated version is deployed.
- No live SoloHost media playback benchmark was available in this build environment.

## Validation
- JS syntax and existing regression/security suite run before packaging.
- Added test `test-media-search-settings.js` to verify settings UI, custom query templates, media CSP allowlist, native file routing and runtime AI knowledge.
- YAML files validated and ZIP integrity checked after packaging.
