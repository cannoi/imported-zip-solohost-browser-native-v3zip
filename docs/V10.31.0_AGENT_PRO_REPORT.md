# SoloHost Browser v10.31.0 — Agent isolation, link integrity, and structured search

Date: 2026-10-16

## Scope implemented

### Phase 1 — Task isolation and resilience
- Agent tasks now ignore client-supplied `history` and `workMemory` for new tasks. State is initialized server-side and is restored only when `resumeTaskId` belongs to the same authenticated browser session.
- Each task gets a distinct ephemeral/private DOM Bridge session and starts with an empty URL stack rather than the user's active page. Terminal done/failed/stopped paths release the isolated session where wired. The new `/continue` endpoint resumes a `limit`/`stopped` task with the same task ID, history, and evidence ledger; clarifications continue through `/answer`.
- New tasks no longer mark an existing task `Superseded` or share its mutable work memory.
- Task-level `errors[]` is persisted separately from findings and is rendered only under Scope & limitations.
- Planner `error`/`exception`/`unknown` actions normalize to a bounded wait action; planner retries increased to three. Structured search failure returns an explicit fallback instruction rather than forcing navigation to a CAPTCHA page.
- Browser UI session setup calls `ensureBridgeSession()` rather than navigating to `example.com` as a side effect.

### Phase 2 — Link integrity
- Added `lib/agent-links.js`: canonical URL handling (tracking parameter removal), balanced punctuation/parenthesis URL extraction, URL classification, and SSRF-guarded link verification using the existing safe fetch path.
- Reports list sources only from the current task's evidence ledger. SERP candidates, search-result pages, CAPTCHA pages, redirectors, and free-form LLM URLs are excluded.
- Valid `[E#]` citations are resolved to ledger-backed source links; invalid citations are labeled unverified. Free-form URLs not present in the current task ledger are removed from the synthesized summary. Unsupported lines are explicitly labeled as not independently verified.
- UI Markdown rendering now supports safe HTTP(S) Markdown links, bare URLs with trailing punctuation handling, and real horizontally scrollable HTML tables. `javascript:` and `data:` destinations are rejected; links use `noopener noreferrer`.

### Phase 3 — Structured search and evidence collection
- Added `lib/agent-search.js`, returning structured `title/url/snippet/site/date/rank` results from public Bing, DuckDuckGo, or Brave HTML, with optional Brave Search API support when `BRAVE_SEARCH_API_KEY` is configured.
- Search engine order defaults to Bing, then DuckDuckGo and Brave. CAPTCHA/consent blocks are treated as blocked results, not instructions to bypass them. If all search options fail, the Agent is told to use a direct public source/feed/sitemap or ask the user.
- Search results are recorded as `kind: serp` candidates and explicitly excluded from evidence-backed findings. A page must be opened/read to be used as report evidence.
- SSRF DNS checks were strengthened for IPv4 special/private ranges and common IPv6 local/private/link-local ranges; redirects continue to be checked by `safeFetch`.

## Not yet verified / incomplete
- No live Playwright/Chromium end-to-end run was possible here because Playwright is not installed in this working environment. The full test suite used the existing proxy fallback/mock fixtures; actual Chromium private-session lifecycle, source reachability, and external search-engine behavior must be validated on the target SoloHost container. DNS to external hosts was unavailable during test execution.
- 15–20 real-task benchmark and the exact two-task acceptance run (Vietnam news digest then iPhone 18 Pro/Pro Max price comparison) are not claimed as completed.
- PDF export, report-library storage, run-to-run diff, fully editable Plan Card, and a cross-tab queue UI are not completed in this release. The existing UI still has a single active run per tab; server tasks are isolated rather than forcibly superseding one another.
- The report grounding check labels unsupported lines and filters URLs/citations, but it is not a semantic entailment model; users should treat unsourced statements as unverified.

## Compatibility and safety
- No stealth, anti-bot evasion, CAPTCHA solving, or cookie copying was added.
- No new package dependency was added. The supplied source ZIP has no Git metadata, so phase-by-phase Git commits could not be created in this workspace.
- Existing browser, AI panel, settings, and media features were otherwise left in place. The intentional behavioral change is that each Agent task uses a clean ephemeral browser session, so it does not inherit the current page or logged-in browser profile.
