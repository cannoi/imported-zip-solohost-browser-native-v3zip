# SoloHost Browser v10.40.0 — Mobile-first Chromium

## Flow (before → after)

**Before:** Context options set `isMobile`/`hasTouch` only when env mobile, but **User-Agent was only applied if `opts.userAgent` was set**, so many sessions used Playwright’s default **desktop** UA with a mobile viewport (inconsistent). v10.39 also **aborted image/media/font** in Chromium routes (hurting real pages + Agent).

**After:**
1. User enters URL → Bridge `createSession({ mobile: true, … })` → Playwright `contextOptions` builds a full **mobile profile**.
2. Persistent and ephemeral contexts share: viewport **390×844**, **Android Chrome Mobile UA**, `isMobile`, `hasTouch`, **DPR 1**, `reducedMotion: reduce`.
3. Every page (including prewarm reuse) gets `setViewportSize` enforced.
4. Chromium loads **real images/media/fonts**; only ad/tracker hosts may be blocked.
5. DOM Bridge sanitizes a **display copy**; live page keeps JS/cookies for Agent.
6. Agent sessions explicitly request `mobile: true`.

## Root causes fixed
1. Missing default mobile User-Agent → sites saw desktop chrome.
2. Image/media/font abort → blank/broken layouts and weaker Agent observation.
3. Prewarm pages could keep wrong viewport until navigated.

## Files changed
- `lib/engine/playwright-engine.js` — mobile profile helpers, contextOptions, persistent launch DPR/UA/reducedMotion, no media abort, viewport enforce, logs
- `lib/engine/dom-bridge.js` — pass mobile + viewport to Playwright
- `lib/backend-agent.js` — agent `mobile: true`
- `test-v10.40-mobile-first.js`

## Env (optional)
- `SOLOHOST_BROWSER_MOBILE=1` (default on)
- `SOLOHOST_MOBILE_W` / `SOLOHOST_MOBILE_H` (default 390/844)
- `SOLOHOST_MOBILE_DPR` (default 1, max 2)
- `SOLOHOST_MOBILE_UA` override
- `SOLOHOST_REDUCED_MOTION=reduce` (default)
