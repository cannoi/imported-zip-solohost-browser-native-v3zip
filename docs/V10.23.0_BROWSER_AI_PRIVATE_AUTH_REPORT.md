# SoloHost Browser v10.23.0 — Browser AI, private tab and access-gate correction

## Implemented
- Removed the legacy external AI-provider selection and endpoint probing from the browser AI agent. AI providers are now local Ollama, OpenAI, and Anthropic only.
- Added an authoritative SoloHost Browser product-knowledge block to the AI system instructions. It documents the actual Chromium + DOM Bridge architecture, private-session expectations, persistence, media and login limitations, and safe user-controlled sign-in.
- Added a deterministic built-in answer for common “what app is this?” questions, so the assistant identifies SoloHost Browser even when no model/API provider is configured. The answer follows Vietnamese/English input.
- Fixed the private-tab click listener being nested inside the history-clear listener. The button now uses the shared `newTab(..., { private: true })` lifecycle, which creates a unique tab identity and preserves the existing private-session rules.
- Removed the implicit default `solohost` access password. Empty `BROWSER_ACCESS_PASSWORD` now means authentication is disabled as the SoloHost configuration help says; a non-empty configured password still activates the gate. Cookie checks now match the exact cookie value rather than a substring.
- Updated the package version and AI panel context to 10.23.0. Added regression checks.

## Not implemented / cannot claim verified
- **noVNC direct desktop takeover:** not added. Current engine launches headless Chromium and exposes isolated Playwright contexts through a DOM snapshot/event bridge. Adding a separate Xvfb/noVNC Chromium would not automatically control the same authenticated context; it also needs a separately secured WebSocket/desktop access policy. A superficial noVNC iframe would be misleading and unsafe.
- **Backend audio streaming to the user:** not added. The existing architecture has no audio capture/encoding/WebRTC pipeline from container audio output to the client. Keeping media elements in a DOM snapshot cannot transport audio generated by the backend process. This requires a dedicated audio transport design or playback in the user's own browser context.
- Full end-to-end browser/login/audio/noVNC tests could not be run in this workspace because Playwright is not installed in the extracted runtime. Source-level and regression checks are included; Docker runtime validation remains required.

## Preserved
Existing browser routes, settings, feedback, library, task scheduling, storage schema, proxy/SSRF controls, engine bridge, and SoloHost package structure were not intentionally redesigned. Historical release notes remain, except obsolete external AI-provider integration references.
