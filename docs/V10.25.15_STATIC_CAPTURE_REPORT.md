# SoloHost Browser v10.25.15 — Chromium Static Capture

## Goal

Add a dedicated capture/export workflow without replacing the interactive Chromium DOM Bridge. Captures run as bounded background jobs so browsing tabs are not navigated or mutated.

## Pipeline

1. Validate the starting HTTP(S) URL and reject embedded credentials and local/private destinations.
2. Run headless Chromium from the already installed `playwright` package; scripts are allowed during capture so client-rendered content can appear.
3. Crawl one page, same-host links, or same-host URLs discovered through `robots.txt` / sitemap, with a hard maximum of 30 pages.
4. Parse rendered HTML with JSDOM + Mozilla Readability; fall back to a main/article/body region when article extraction fails.
5. Sanitize extracted content server-side with `sanitize-html`; remove active scripts and form controls.
6. Write responsive HTML pages, an index and manifest; rewrite links between captured pages to local filenames when possible.
7. Package the site folder as a ZIP. Files and manifest remain under `SOLOHOST_DATA_DIR/static-captures/<job-id>`.

## UI and API

- UI: `/static-capture.html`, also linked from the browser settings menu.
- `POST /api/browser/static-captures` — `{ "url": "https://example.com/article", "scope": "single|domain|sitemap", "maxPages": 12 }`
- `GET /api/browser/static-captures/:id` — progress/status
- `GET /api/browser/static-captures` — recent in-memory and persisted completed captures
- `GET /api/browser/static-captures/:id/files/:file` — HTML preview
- `GET /api/browser/static-captures/:id/site.zip` — ZIP download

## Dependencies and why

- **Playwright Chromium** is reused from the app's existing `playwright@1.51.1` dependency.
- **`@mozilla/readability`** provides article extraction from rendered DOM snapshots.
- **`jsdom`** supplies a server-side DOM for Readability and relative URL normalization.
- **`sanitize-html`** strips unsafe markup and attributes before generated content is served.
- **`archiver`** packages output without shelling out to system ZIP binaries.

Crawlee's `PlaywrightCrawler` is a solid choice for high-volume recursive crawling and offers request queues, retries, browser pooling and autoscaling. For SoloHost Pi's low-memory target and a small bounded capture feature, this implementation avoids adding a second crawling orchestration layer; it uses one Chromium page and a sequential queue. Crawlee can be considered later if durable distributed queues or high concurrency become requirements.

## Security and resource controls

- Only HTTP(S) URLs without username/password are accepted.
- Localhost, `.local`, `.internal`, `.lan`, private IP ranges and private DNS resolutions are rejected for the capture workflow, even though the normal browser may support local apps.
- Chromium requests are intercepted and revalidated; redirects and subresources go through the same route policy.
- One concurrent job by default; configurable 1–4. Default 12 pages, hard cap 30; navigation timeout default 25 seconds.
- API has a per-IP capture start rate limit. Generated content is sanitized and served with restrictive CSP and `nosniff`.
- Captured content can still contain text from untrusted sites; it is not executed as source code.

## Known limits

- This is a **static reading site**, not a complete offline mirror or an exact reconstruction of the original UI.
- Scripts, forms, authentication, SPA interactions, live feeds and protected/DRM media are not reproduced.
- Images/media may remain linked to the original public website, so some resources need internet access when viewing the capture.
- Same-host crawling is deliberately conservative; it does not traverse subdomains.
- Captures from authenticated browser tabs are not reused in this first version; the job creates a clean context.
- A Docker build and real live capture could not be verified in this environment because npm package installation/network access timed out. The existing regression suite and source/syntax tests pass; extraction tests are skipped locally when the newly added npm dependencies are unavailable. Validate the Docker build and a real public URL on SoloHost before treating runtime capture as production-verified.
