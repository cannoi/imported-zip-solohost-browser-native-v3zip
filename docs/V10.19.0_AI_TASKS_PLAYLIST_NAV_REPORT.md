# SoloHost Browser v10.19.0 — AI Tasks, Playlist, Navigation and Site Policy

## Changes
- Replaced the former Scripts panel with AI Tasks, removed manual task creation inputs, and reduced built-in templates to five practical examples.
- AI Panel can create a persisted daily YouTube music task from clear natural-language instructions (time and duration). The task scheduler runs in the configured IP-derived timezone while the app UI remains open.
- Playlist items use official embed URLs for supported YouTube, Vimeo and TikTok links; playback remains inside the Playlist panel instead of navigating away.
- Added optional HTTP Basic access password via `BROWSER_ACCESS_PASSWORD` and SoloHost configuration. Empty value disables authentication.
- Added best-effort public-IP locale/time-zone hint, with local fallback. Manual language selection remains respected.
- Improved keyboard Back/Forward handling and stale Bridge session recovery.
- For Google rejected sign-in redirects, Open ↗ targets the legitimate `continue` URL in the external browser; no auth bypass or cookie transfer is attempted.
- Bing challenge-like URLs are attempted in the direct frame so the user can solve the challenge themselves; site policy may still prevent framing.

## Limits
- Scheduled actions only run while the browser UI is open; a server-side scheduler cannot start playback in a closed user's browser.
- Public-IP locale lookup depends on `ipapi.co` availability. It is best-effort and falls back to the configured/local timezone.
- Sites can disable embedding, require login, or enforce region/age/DRM restrictions. The app does not bypass CAPTCHA or site authentication policy.
- HTTP Basic auth protects this app origin; it does not sign the user into external sites.
