# SoloHost Browser v10.25.21 — v10.20.x Website Extraction & Presentation Restoration

## Scope and baseline

The implementation was compared against the available `solohost-browser-v10.20.5-agent-tools-links.zip` and `solohost-browser-v10.20.0-unified-ai-memory-music.zip` sources. The restoration baseline is **v10.20.5**, the newest v10.20.x archive available in the workspace. This is a targeted restoration of website extraction/presentation behavior, not a wholesale downgrade of the application.

## What was restored

1. **Live website DOM extraction**
   - `lib/engine/playwright-engine.js` again calls `markInteractive(page)` directly for the website snapshot, matching the v10.20.x contract.
   - It captures the live Chromium DOM after scripts have run, tags actionable elements with stable bridge IDs, and returns the sanitized display HTML plus URL/title, visible-text length, control count, media and login/challenge signals.
   - It keeps site stylesheets, classes, inline styles, forms, and normal page structure in the display copy. It removes executable scripts and unsafe nested frames from the copy while the actual site continues running in Chromium.
   - Existing `focused` mode remains opt-in; it is not forced on users.

2. **Website presentation in the Bridge**
   - Removed the post-v10.20 page-family template layer from the active rendering path.
   - Restored the v10.20.x conservative Bridge stylesheet and mobile viewport behavior, including the specific Bing result-layout adjustments.
   - Relative asset URLs still use a validated HTTP(S) base URL. The sanitizer continues to strip supplied `<base>` tags before inserting its own validated base, preserving the later security hardening.
   - Kept the allowlist for supported HTTPS media embeds, and kept the SoloHost navigation bridge so links do not unexpectedly escape to the host browser.

3. **Reader extraction and Reader Mode**
   - Confirmed `public/reader-injector.js` is byte-for-byte the v10.20.5 implementation and remains loaded from `public/index.html`.
   - Confirmed the Reader button, `SoloReader.extractCurrentPageDOM`, and `SoloReader.toggleReaderView` are still wired in `public/app.js`.
   - The old `lib/reader-view.js` is not reactivated: in the v10.20.5 archive it has no import or route wiring, and its `clean_html` data contract does not match the active Bridge snapshot API. Copying it into the running route table without adapting the API would add dead code rather than restore a working feature.

4. **Routing behavior**
   - Restored the v10.20.5 `lib/engine/content-router.js` policy/classifier instead of using the later page-family template classifier. This intentionally restores the older routing behavior for social/auth, video, search, and article URLs.

## Newer code removed from the active tree

- Deleted `lib/engine/content-pipeline.js`: the newer shared metadata/capture wrapper is no longer in the active snapshot path.
- Deleted `lib/engine/layout-templates.js`: the later page-family presentation templates are no longer applied.
- Replaced `test-content-templates.js` with `test-legacy-content-restoration.js`, and updated the tab-sync regression test to check the restored contract.

These deletions are intentional and limited to the newer website-reading/presentation layer the user asked to replace.

## What was deliberately preserved

- v10.25.20 popup ownership and tab/session synchronization fixes.
- 12-tab/session capacity alignment and persistent Chromium profile/session behavior.
- Current link routing for `_blank`, Ctrl/Meta-click, and `mailto:`/`tel:` handling.
- SSRF protections, HTML sanitization, safe media iframe allowlist, and validated asset base URL.
- noVNC handoff, native client audio, AI memory/tasks, music/playlist controls, and other unrelated features.
- Existing Reader Mode files and UI wiring.

`lib/engine/dom-bridge.js` was changed only in its active page-presentation styling block; the current tab/session reuse and security code was retained.
