# SoloHost Browser v10.25.23 — Website Pipeline Reversion Report

## Goal and comparison baseline

This release compares the current v10.25.22 package against the available v10.20.0 reference archive. The v10.20.1 and v10.20.2 source archives were not available, so this report does not claim an exact comparison with those releases.

The scope is intentionally narrow: restore the older website acquisition/presentation path where post-baseline changes altered page snapshots, links, iframe behavior, request identity, or layout. Keep independent browser/application improvements unless they are directly part of that website pipeline.

## Completed changes

1. **DOM Bridge HTML sanitizer restored.** `sanitizeHtml()` in `lib/engine/dom-bridge.js` is restored from the v10.20.0 reference. Removed the newer behavior that stripped page-supplied `<base>` tags, forced every anchor to `target="_self"`/`data-sh-nav`, and changed base URL validation. The existing legacy media-frame allowlist, script/event-handler sanitization, viewport and Bridge stylesheet remain as they were in v10.20.0.
2. **Proxy renderer restored.** `lib/frame-proxy.js` is restored to the v10.20.0 reference version. This removes post-baseline changes to injected layout CSS, direct anchor rewriting, target-blank handling, and Bing redirect unwrapping. Existing baseline URL validation/SSRF protections and proxy behavior remain.
3. **Chromium request identity restored.** Removed the added stealth fingerprinting module and its injected scripts, client-hint headers, spoofed Windows desktop User-Agent, and stealth launch arguments. Restored the v10.20.0 Android/Linux Chromium User-Agent defaults and mobile-default setting. The baseline ad/tracker policy remains; this release does not add a new broader blocklist.
4. **Website verification handoff page removed.** The newer custom challenge handoff that replaced the website snapshot with a SoloHost-authored page is removed from `lib/engine/dom-bridge.js`. Existing baseline verification handling remains; no CAPTCHA is solved or bypassed.
5. **Website link handling restored in the UI.** Removed the post-baseline universal anchor interceptor and Bing/DuckDuckGo redirect unwrapping helper from `public/app.js`. Restored the legacy `data-sh-id` click behavior and legacy `solohost-navigate` message contract. The tab ownership guard remains so late events from a background tab do not overwrite the active tab.
6. **Bridge iframe policy restored.** Restored the v10.20.0 iframe sandbox permission string, including `allow-popups`, and restored `base-uri 'self'` for the Bridge view CSP in `server-app.js`.
7. **Presentation-changing refresh workaround removed.** `softRefreshActiveBridge()` is again a no-op, matching the older behavior; it no longer mutates/reloads broken image URLs during a refresh call.
8. **Regression tests and release version updated.** Version is now `10.25.23`. Added `test-v10.25.23-legacy-extraction.js`, updated the tab-sync regression filename/assertions, and adjusted proxy/iframe expectations to test the restored baseline rather than the removed newer behavior.

## Important upgrades retained

- Tab-to-Bridge/Chromium session mapping and session reuse.
- Popup ownership scoped to the opener tab and unowned-page recovery; the engine does not blindly take another tab's page.
- Persistent browser profiles and storage-state/IndexedDB persistence support.
- Separate noVNC/headed login browser and its cookie-state synchronization.
- AI compatibility, unified AI/memory, Browser Agent and agent tools.
- Music Library, playlist controls, client-native audio playback, YouTube routing and media/search settings.
- Private tabs, context menu, access-password gate, app UI, logs, security/SSRF protections, Docker/SoloHost configuration, Reader injector, and unrelated tests.
- Session capacity/TTL and tab-safe late-response protections.

## Not completed / environment limitations

- **Live website rendering was not verified in a real SoloHost container.** The test environment reports `playwright_not_installed`; therefore the Chromium runtime, real login flows, and live DOM rendering could not be exercised here.
- Public-hostname/DNS checks and the example.com navigation test were skipped/failed because external DNS resolution was unavailable. Local SSRF block tests passed.
- Page-load latency, memory/RAM use, and multi-tab behavior under the actual SoloHost runtime were not measured.
- Exact v10.20.1/v10.20.2 behavior remains unverified because those archives were unavailable. v10.20.0 is the verified reference.

## Intentional trade-offs

Restoring the older link and iframe behavior means some newer conveniences are intentionally absent: Bing/DuckDuckGo tracking-link unwrapping, universal link interception, the explicit `mailto:`/`tel:` host handoff, and the newer `target=_blank` proxy-to-tab translation. This is deliberate to restore the available baseline website path, not an accidental loss of files. The core tab-safety/session improvements remain active.
