# SoloHost Browser v10.30.1 — Agent Hang Fix Report

## Log diagnosis

The supplied logs show repeated `bridge.pw_event_fail error=session_not_found`, plus `bridge.playwright_nav_fail` and `bridge.keep_engine_no_proxy` with the same error. This indicates the DOM Bridge retained a Playwright session ID that the Playwright engine no longer had registered. Navigation then failed while the bridge kept the engine path, and stale UI events continued to hit the missing session.

The Agent also emitted the same required-source gate status. The prior gate could repeatedly `continue` when a `done` action was proposed while sources remained missing. Navigation failures were not consistently recorded as source failures, so the gate could not distinguish an inaccessible source from a source never attempted.

## Changes

- Added `recreatePlaywrightSession()` in `lib/engine/dom-bridge.js`. On `session_not_found`, navigation now creates a fresh engine session and retries the navigation once without recursively re-entering the same in-flight navigation promise.
- Event dispatch now attempts session recovery, restores the last HTTP(S) URL, refreshes the snapshot, and returns a recovery result rather than endlessly logging the stale-session failure.
- Navigation action results in `lib/backend-agent.js` now update `task.sourcesStatus`; failed/empty navigation is not counted as a successful visit.
- Persisted `sourcesStatus` for task resume.
- Added a bounded retry to the required-source completion gate. If the Agent still proposes completion without coverage after a retry, it records explicit blocked reasons and allows a partial report rather than remaining indefinitely on the same status.
- Bumped package version to 10.30.1 and added a regression test to the `npm test` script.

## Validation

- Syntax checks: `lib/engine/dom-bridge.js` and `lib/backend-agent.js`.
- Static regression checks verify recovery wiring, failure tracking, persisted source status, and bounded completion retry.
- Live recovery against the user's exact Docker runtime and real news websites is not claimed by this report; it must be verified after deploying the ZIP.

## Full-suite result and known unrelated failures

`npm test` was run after the patch. JavaScript syntax checks passed (77/77), and tests before `test-mobile-resilience.js` passed. The full script stops at `test-mobile-resilience.js` because it expects three Playwright engine fallbacks, while `lib/engine/playwright-engine.js` intentionally documents and implements Chromium-only behavior. This assertion is outside the session-recovery change and was not “fixed” by adding Firefox/WebKit or changing browser architecture.

Additional legacy tests run individually expose other stale source-contract assertions (`test-bing-default.js`, `test-focused-content.js`, `test-interaction-performance.js`, `test-context-menu-tabs.js`, `test-v10.25.23-tab-sync.js`). They are not changed by the session recovery patch. Tests directly related to the Agent (`test-backend-agent.js`, `test-agent-report.js`, `test-agent-evidence-v1029.js`, `test-agent-v1030.js`, and `test-agent-session-recovery-v1031.js`) passed.

The local test environment does not have Playwright installed and external DNS resolution fails, so an end-to-end live Chromium recovery test could not be performed here. Deploy to a staging SoloHost instance and verify that logs show `bridge.playwright_session_recovered` / `bridge.playwright_nav_recovered` rather than repeated `session_not_found`.
