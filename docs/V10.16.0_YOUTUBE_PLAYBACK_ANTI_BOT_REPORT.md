# v10.16.0 — YouTube playback routing and site-policy compliance

## Evidence from supplied logs
- The app navigated to `https://m.youtube.com/shorts/QAhwh2aZzK4` and emitted repeated `client.bridge_render_audit` warnings. It did not show `proxy.youtube_player` or a player-specific error code in the supplied excerpt.
- This points to a routing mismatch: the video was loaded through the Playwright/DOM Bridge path, whose display snapshot sanitizes scripts and can omit iframe/media elements. The server already had an official YouTube embed player route, but Bridge-originated video clicks did not reliably enter that route.
- `playwright.request_filtered` records that a filtering rule matched; alone it does not prove YouTube blocked the video. Brave's `/help/pow-captcha` route indicates a challenge page was presented, but the log does not identify the exact signal that triggered it.

## Changes
- Route YouTube `/watch?v=…`, `/shorts/…`, `/live/…`, `/v/…` and `youtu.be/…` links from the interactive snapshot to the existing server-side official-player shell.
- Classify direct YouTube video URLs as the local proxy player route rather than rendering a script-stripped Bridge snapshot.
- Add `youtube.video_handoff` diagnostic logging and capability/AI knowledge.
- Documented that anti-bot/CAPTCHA checks are not bypassed. No fingerprint spoofing, CAPTCHA solving, stealth flags, proxy rotation or disabling site protections was added.
- Other modules and the existing official embed/player implementation remain in place.

## Limits
- No live YouTube playback was possible in the isolated test environment. Official embed playback can still be refused for videos with embedding disabled, age/region restrictions, account requirements, network issues or unsupported codecs. In those cases, use the explicit Open ↗ action.
- The supplied log excerpt has no YouTube iframe error code or `proxy.youtube_player` event, so it supports the Bridge-routing diagnosis but cannot prove every playback failure has that same cause.
