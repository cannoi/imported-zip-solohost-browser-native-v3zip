# SoloHost Browser v10.25.16 — Shared Content Pipeline Report

## Goal
Replace duplicated Bridge/static-capture extraction logic with a shared pipeline while keeping the same persistent Chromium profile.

## Architecture
- `lib/engine/content-pipeline.js`: common live-page metadata inspection, conservative DOM-signal classification, JSON-LD capture, link extraction, and Mozilla Readability extraction.
- `lib/engine/playwright-engine.js`: Bridge calls `contentPipeline.captureLivePage()` around the existing interactive snapshot and exposes `createCapturePage()` for auxiliary pages inside an existing persistent BrowserContext.
- `lib/engine/static-crawler.js`: no longer launches its own isolated Chromium browser; it uses `createCapturePage()` with `solohost-default-profile` by default (or a validated profile key) and delegates article extraction to the common pipeline.

## Why not Crawlee as the Bridge replacement?
Crawlee's PlaywrightCrawler owns its browser/page lifecycle and opens pages for requests. It is excellent for large queued crawls, but adding it as the Bridge's core extractor would introduce a second lifecycle layer and would not automatically reuse the current live user's BrowserContext. The current app already has Playwright and persistent profile management. The selected design uses Playwright's existing Page/BrowserContext plus Mozilla Readability for article extraction, avoiding a second browser stack. Crawlee can be considered later for a separate high-volume crawling mode.

## Profile semantics
Static Capture uses an auxiliary page in the same persistent BrowserContext, so it shares cookies, localStorage, IndexedDB and browser storage. It does not navigate the user's visible tab. For a non-default profile, the API can pass a validated `profileId` (32 hex chars) to select that profile. Private/ephemeral profiles should not be used for durable capture jobs.

## Compatibility
The Bridge still emits its interactive DOM snapshot, safe media iframe treatment, `data-sh-id` controls and layout CSS. Readability is metadata/article extraction and does not replace the DOM snapshot for social feeds, video sites, search pages, forms or authenticated applications. This avoids flattening all sites into static articles.

## Security
Static Capture retains URL validation and request interception for every network request, same-host URL discovery, bounded page count and sanitized HTML output. The capture page is closed after the job; the shared BrowserContext/profile remains open.

## Tests
`npm test` passed the existing suite plus source-level assertions for shared profile reuse and shared pipeline wiring. The Readability extraction tests were skipped because `jsdom`, `@mozilla/readability`, and related npm dependencies are not installed in this execution environment. Docker/Chromium end-to-end validation was not possible here.
