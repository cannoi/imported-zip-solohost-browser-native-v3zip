# SoloHost Browser v10.39.0

## Goals
Never-blank display, YouTube usable without SPA shell, lighter Chromium backend, mobile layout clamp.

## Implemented (verified in unit tests / syntax)

### Phase 1 — Never blank + YouTube
- `lib/adapters/youtube.js`: home form, search via `ytInitialData`, player `youtube-nocookie` + 4.5s fallback card
- `lib/render-error.js`: structured error cards (`data-sh-error-card`)
- `lib/frame-proxy.js`: YouTube path uses adapter; empty sanitize → error card; proxy fail → error card
- `dom-bridge.sanitizeHtml`: empty output → error card (not `''`)
- Client blank watchdog for YouTube → force PROXY once
- Test: `test-v10.39-youtube-blank.js` **PASS** (fixture ytInitialData, no live YouTube network)

### Phase 2 — Backend load (partial)
- Chromium `route`: abort `image`/`media`/`font` (+ existing ad filter)
- `persistSessionState`: debounced via `schedulePersist` (~60s), not every `page.on('load')`
- `indexedDB: false` on storageState when previously true

### Phase 4 — Mobile layout (partial)
- Bridge CSS: `overflow-x:hidden`, box-sizing, max-width on media
- `public/layout-guard.js` + index script (clamp overflow in same-origin iframe)

## Not done / not verified on SoloHost
- Full render-router Tier A HTTP-first for all sites
- AI Search providers (Gemini/OpenAI grounding)
- ETag/async gzip, static maxAge dedupe
- Full dead-code Tier A/B/C list
- Live YouTube network + CAPTCHA pages
- PERF_BASELINE.json numbers on 2 vCPU host

## Risks
- Aborting images in Chromium may make screenshot fallback blankier (error card still shows)
- ytInitialData shape changes → search falls back to error card with Open ↗
