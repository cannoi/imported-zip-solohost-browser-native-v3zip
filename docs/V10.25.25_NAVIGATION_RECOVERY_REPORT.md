# SoloHost Browser v10.25.25 — Navigation Recovery Fix

## Report summary

Fixed a backend/UI mismatch where Playwright returned a navigation error without throwing. The DOM Bridge previously proceeded to capture the live page anyway, which could return the previous page's DOM and URL as if the requested URL had loaded.

## Changes

- `lib/engine/dom-bridge.js`: preserve the previous URL during navigation; detect Playwright error responses that leave the browser on the old page or a non-HTTP browser error URL; route that single navigation through the existing sanitized proxy fallback instead of returning stale DOM; log the requested host and failure; retry a still-live Playwright session on the next navigation rather than permanently pinning the tab to proxy mode; detect stale-content races after navigation.
- `lib/engine/playwright-engine.js`: keep URL hash fragments in same-URL comparison. Hash-based SPA routes now navigate instead of being mistaken for the same document.
- Runtime version strings and tests updated to v10.25.25.
- Added `test-v10.25.25-navigation-recovery.js` and included it in `npm test`.

## Kept unchanged

No changes were intended to AI, music, persistent profile storage, tab synchronization, popup ownership, noVNC, SSRF policy, website sanitization rules, or Google authentication policy. Existing proxy fallback remains sanitized and subject to existing URL safety checks.
