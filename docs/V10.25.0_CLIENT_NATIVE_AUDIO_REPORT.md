# SoloHost Browser v10.25.0 — Client-native audio playback and AI Kernel update

## Implemented

- Added a native HTML `<audio controls>` player to the persistent music dock. It runs in the browser/device that opened SoloHost, not in the backend Playwright process.
- Music Library recognizes direct HTTP(S) audio file URLs with common extensions (`mp3`, `m4a`, `aac`, `wav`, `flac`, `opus`, `oga`, `ogg`). Selecting one stops the iframe player, loads the direct URL in the client audio element, and attempts playback; native controls remain available when autoplay is blocked.
- Wired audio play/pause state, end-of-track playlist advance, next/previous and stop controls. Added client-side playback/error diagnostics (`playlist.direct_audio_play`, `playlist.direct_audio_error`).
- Updated Music Library input copy and added responsive dock styling.
- Updated `lib/app-adapter.js` AI Kernel knowledge and offline/local bilingual responses. The AI now distinguishes client-native direct-file playback from backend audio streaming, and does not claim arbitrary backend Chromium audio is transported to the UI.
- Bumped app/runtime version to 10.25.0 and updated regression expectations. Added `test-v10.25.0-audio.js` to `npm test`.

## Not implemented / not verified

- **Backend audio capture/streaming is not implemented.** Audio generated by arbitrary pages inside backend Chromium is not piped to the user's device. The existing DOM Bridge cannot carry that audio by itself.
- Direct audio playback requires a URL that the user's browser can access directly. URL extensions are used as a practical selector, not proof of actual MIME type; signed URLs without a recognized extension, HTML pages masquerading as media, unsupported codecs, authorization headers/cookies, source hotlink restrictions, and network failures may not play.
- Autoplay may be blocked by browser policy; users may need to press Play. This client-native path does not solve site DRM, CAPTCHA, anti-bot, login or licensing restrictions.
- No real SoloHost/Docker browser session was available for an audio hardware/network playback smoke test. Tests validate source wiring, AI knowledge, syntax and regressions, not audible output from a deployed host.

## Compatibility / scope

- Existing official YouTube/Vimeo/TikTok iframe playback remains in place. Direct audio uses a separate `<audio>` element and clears the iframe to avoid competing playback.
- noVNC and its existing configuration were not redesigned. noVNC provides visual/input access to the backend desktop; it is not an audio transport.
- Existing API contracts and persisted playlist item format are unchanged; URLs already stored as playlist items can be played if they match the direct-audio rule.

## Validation

- Full `npm test` suite passes, including JavaScript syntax (60/60), existing browser/security/AI/playlist/noVNC regression tests and the new audio/AI knowledge test.
- Targeted `node --check` checks pass for the modified browser/server/AI files.
- Docker image build and live audio output were not verified in this environment; external DNS is unavailable in some existing network tests.
