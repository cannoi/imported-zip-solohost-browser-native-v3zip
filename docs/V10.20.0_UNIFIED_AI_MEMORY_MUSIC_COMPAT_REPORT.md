# SoloHost Browser v10.20.0 — Unified AI, Memory, Music Library and Browser Compatibility

## Completed
- Repositioned the embedded Music Library player and playback controls above the saved track list. Added play/pause, previous/next, shuffle, repeat off/all/one. Shuffle and repeat selections persist locally. YouTube IFrame API state messages are used for best-effort automatic end detection; external providers can restrict controls or embedding.
- Removed the dedicated Agent-mode toggle. One chat input routes clear imperative browser operations to Browser Agent while ordinary questions and planning remain chat. Browser Agent continuation context persists locally between reloads; sensitive actions still use the existing confirmation UI.
- Added persistent profile-scoped AI history, memories and reusable skills stored in `/app/data/ai-memory.json`. The browser sends a random local profile ID; storage is bounded and credential-like strings are rejected. Explicit phrases such as “remember that …” and “save skill: name: instructions” are supported. “Forget all memories” clears saved memory and transcript.
- Increased AI request/history limits and passed recent conversation, memories and skills to the configured provider. The model can suggest stable non-sensitive memories, which are filtered by the server before persistence. Local guide mode can show saved memory and recent context, though it does not have the full reasoning capability of a configured AI provider.
- Added natural-language task modification for the most recently created task: update schedule time/duration and pause/resume across separate chats. New scheduled task parsing supports AM/PM. The saved task ID and conversation history persist across chats.
- Browser profile persistence now keys off a stable local profile ID instead of client IP, avoiding cookie/storage profile changes when the client IP changes. Private sessions remain non-persistent. The new Playwright context receives the app UI locale and best-effort public-IP time zone. The first session waits briefly for locale detection, with a fallback if geolocation is unavailable.
- Audited browser identity: the main Playwright context uses the User-Agent matching the bundled Chromium 131 profile, with mobile viewport/touch settings kept consistent when mobile mode is enabled. The server-side scheduled-media resolver identifies itself honestly rather than claiming to be a different browser. No webdriver hiding, fingerprint spoofing, CAPTCHA solving, auth-cookie copying, or anti-bot bypass was added.
- Changed the container system time-zone fallback to UTC; UI/scheduler prefer the public-IP-derived zone. Fixed the SoloHost config field by removing unsupported `id`, and updated the SoloHost compose port declaration to let SoloHost assign the public port.
- Preserved existing navigation, tabs, privacy modes, bookmarks/history, settings, feedback, logs, provider setup, browser engine bridge, SSRF protection, auth handoff and existing AI Tasks.

## Validation
- `npm test`: PASS, all included static/unit/regression tests. JavaScript syntax scan: 54/54.
- YAML parse: PASS for both config files and both Compose files.
- New regression test covers persistent memory CRUD/filtering, Music Library layout/control contracts, single chat routing, stable profile identity and per-session locale/time zone.
- SSRF regression: private hosts and unsafe ports blocked. External DNS test skipped because DNS is unavailable in this build environment.

## Not fully verified / limitations
- Express and Playwright packages are not installed in this build environment, so the HTTP routes and real Chromium page were not end-to-end launched here. The test suite validates source/contracts but cannot prove SoloHost runtime behavior.
- No real YouTube/Vimeo/TikTok playback or Google/Bing login was exercised. Embedding, repeat/end notifications, login and CAPTCHA remain dependent on official provider policies.
- Full SoloHost RAM/page-load/multi-tab benchmarks were not run.
- Headless Chromium can still be identified by websites, and public-IP reputation/rate limits can trigger verification. This update deliberately does not bypass those protections; use the official Open ↗ flow for challenges or restricted authentication.
