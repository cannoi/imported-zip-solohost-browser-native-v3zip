# SoloHost Browser v10.30.0 — Agent upgrade report

## Scope and approach
The v10.29.0 ZIP was inspected before changes. This release prioritizes the prompt-loss / clarification-resume blockers, task understanding scaffolding, progress-plan visibility, and conservative browser behavior. Unrelated browser UI and media features were left in place.

## Implemented
- Task briefs are retained up to 20,000 characters; the display title is not used as the task payload limit.
- Added `lib/agent-task-analyzer.js` with deterministic task-kind, goal, steps, source URLs, time-window, language, guardrails, output-format and risk extraction. The original brief remains available to the planner.
- Added a common terminal-message resolver for `question`, `message`, `text`, and `reason`; ask-user events carry question/options/kind fields.
- Added authenticated `POST /api/browser/agent/sessions/:sid/tasks/:tid/answer`; answers are stored as clarifications on the existing in-memory task and continue the same task ID instead of concatenating into the original prompt.
- Task disk snapshots now retain brief/spec/clarifications/checklist; task start assigns a checklist and a basic plan. The client renders the returned plan and preserves the task ID for clarification answers.
- Improved the done gate so missing required sources that are not marked failed/blocked defer completion while step budget remains.
- Reduced observation text to 3,500 characters and elements to at most 80 for bounded prompts. Generic heuristic searches use DuckDuckGo rather than defaulting to Google.
- Removed stealth/fingerprint-masking hooks and forced spoofed desktop/mobile user agents from the Playwright engine. This is an intentional compliance change: the browser should not attempt to evade anti-bot controls. User-selected explicit user agents remain possible.
- Version updated to 10.30.0; added `test-agent-v1030.js`.

## Verification performed
- `node --check` passed for modified server, agent and client JavaScript files.
- `node test-agent-v1030.js` passed.
- The full `npm test` command was attempted. It passes syntax, baseline extraction, static checks, security tests, bridge tests, AI compatibility tests, Browser Agent tests, backend-agent tests, YouTube tests, and YouTube click-routing tests, but stops at `test-mobile-resilience.js` because that test expects a three-engine Chromium/Firefox/WebKit fallback (`'chromium', 'firefox', 'webkit'`) while the supplied code only initializes Chromium. This mismatch appears unrelated to the Agent changes and was not changed because replacing the browser-engine architecture would violate the minimal-change constraint.
- Runtime integration with a real AI provider and live public news feeds was not possible to verify in this environment. Existing tests also warn that Playwright is not installed in this unpacked test environment and external DNS is unavailable.

## Not yet implemented / not verified
- Full interactive Plan Card editing (add/remove/reorder steps and source toggles) and editable source-level controls.
- Complete `agent_step` schema unification across tool/JSON modes, source-status lifecycle, full 60-step/20-minute budget orchestration, bounded parallel article tabs, and robust `publishedAt` timezone normalization.
- Full news playbook execution across all five RSS sources, source-level article reading, topic deduplication/category assignment, and trending-keyword extraction are not yet wired as a complete deterministic pipeline.
- Evidence-led report builder with per-claim `[E#]` citations, grounding rejection, report filtering, HTML/PDF export, run comparison, and save-as-skill are not complete.
- CAPTCHA/manual-action question UX and quick-choice buttons are only partially surfaced; the user must solve CAPTCHA themselves. No CAPTCHA solving or anti-bot bypass is added.
- No real-provider 15–20 task benchmark was run. Do not treat the scaffolding or static tests as proof of end-to-end report quality.

## Compatibility / intentional changes
The Playwright anti-detection hooks were removed to comply with the explicit no-anti-bot-evasion guardrail. Search heuristic fallback changed from Google to DuckDuckGo to reduce repeated verification loops without bypassing them. Other browser capabilities were not intentionally redesigned.
