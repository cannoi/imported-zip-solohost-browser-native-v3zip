# SoloHost Browser 10.9.9 — Bing Default / Google Login Diagnostics

## Changes
- Bare search text from the omnibox is routed to `https://www.bing.com/search?q=...`.
- `/api/browser/go` defaults to Bing and accepts `engine=bing`; explicit Google/YouTube searches remain supported.
- Browser Agent general searches and AI navigation instructions now prefer Bing.
- Bridge snapshot CSS adds Bing-aware responsive layout rules for the search box, results column, result titles/snippets, and narrow displays.
- Google `/sorry/` fallback query extraction only accepts a real `/search?q=...` target, including a verified `continue` URL. Challenge tokens are not treated as search terms.
- A Google account sign-in rejection is logged as `bridge.google_login_rejected` to distinguish upstream policy rejection from display errors.

## Scope preserved
- No removal or replacement of Chat, Feedback, Settings, Logs, AI, browser history/bookmarks, SSRF validation, session isolation, or SoloHost config fields.
- YouTube host handling and official player flow are not replaced by this change.
- No attempts to evade Google CAPTCHA, unusual-traffic checks, account policy, or sign-in restrictions.

## Validation results
- `npm test`: PASS (exit code 0), including syntax scan `43/43`, core contracts, security/SSRF, bridge, AI compatibility, Browser Agent, backend agent, YouTube/Google regressions, mobile recovery, Bing default and performance/SSRF checks.
- YAML parse: PASS for `docker-compose.yml`, `solohost/docker-compose.yml`, `config_options.yml`, and `solohost/config_options.yml`.
- Google fallback regression verifies normal search terms and a safe `continue` URL are retained while challenge-token-like `EgQ...` values are rejected.
- SSRF checks blocked loopback and port 2375 as expected. Public-hostname DNS check was skipped because external DNS was unavailable; example.com navigation/performance could not be measured in this environment.
- Live Bing rendering, Google account login and YouTube playback were not tested in an actual SoloHost deployment. Google may still require the system browser for account sign-in; upstream security checks are intentionally not bypassed.
