# SoloHost Browser 10.12.0 — Adaptive Layout Report

## Decision

Use the real Chromium DOM as the source of truth and create a sanitized display snapshot. Do not rebuild every website into a new bespoke UI: this is brittle, breaks interactions, and costs more maintenance. The default `adaptive` mode now preserves the site’s own CSS/classes/inline styles and grid/flex structure, then adds only conservative viewport, overflow, responsive-media and reduced-motion rules.

## Common page families

- **Search:** keep the original result layout, filters, query form and pagination; prevent long links from overflowing.
- **Video:** keep native video/audio and retain HTTPS iframe embeds only from known media providers. Use Open ↗ when a site needs DRM, full login, or complex player APIs.
- **Commerce:** preserve product cards, image galleries, price/variant selectors, cart controls and responsive grids; lazy-load images and remove only recognizable ad slots.
- **Blog/news/article:** preserve typography, article columns, image captions and article structure; remove scripts only from the display copy.
- **Social:** preserve the site’s feed/card layout and form controls; dynamic content still depends on the live Chromium engine.
- **Generic:** preserve the site layout and apply a common safety/responsive layer.

These are classifications for conservative CSS tuning, not separate custom renderers. This avoids a large brittle rules engine and reduces regression risk.

## Changes made

- Default `SOLOHOST_BROWSER_CONTENT_MODE` is `adaptive`; root and SoloHost compose configuration updated accordingly.
- Preserves stylesheet links, inline styles, class names and `srcset` in adaptive mode. The previous focused mode remains opt-in.
- Removes scripts from the transferred snapshot but leaves the live Playwright page untouched, so Bridge clicks, text input and form submission continue to operate against the actual DOM.
- Preserves native video/audio elements and only allows a small set of HTTPS media iframe providers (YouTube, Vimeo player, TikTok embeds, Spotify, Twitch player, Dailymotion). Arbitrary nested frames remain removed.
- Adds page family classification and conservative responsive/reduced-motion CSS; does not force all page regions to `display:block`, and does not impose a global one-column layout.
- Retains conservative ad/tracker request filtering and recognizable ad-slot removal. Ads sharing first-party content APIs may remain to avoid breaking the website.

## Tests and limits

- Added `test-adaptive-layout.js` for adaptive default, preservation of classes/forms, safe media iframe allowlist, and rejection of untrusted nested frames.
- Existing navigation, security/SSRF, Bridge, AI compatibility, browser agent, YouTube/Google fallback, mobile, Bing, focused-content and performance tests remain in the test suite.
- This environment cannot verify visual fidelity or actual playback on a live SoloHost installation. DRM, CAPTCHA, anti-bot rules, complex canvas apps, and some site-specific embedded players may still require Open ↗.
- Third-party stylesheet loading remains necessary to preserve layout; scripts are still stripped from the display copy. External stylesheet URLs may make extra network requests, a trade-off for retaining the website’s form. Known ad/analytics domains are filtered by the engine when the request matcher recognizes them.
