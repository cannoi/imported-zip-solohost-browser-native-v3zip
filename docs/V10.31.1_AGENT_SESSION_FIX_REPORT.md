
# SoloHost Browser v10.31.1 — Agent backend session creation fix

## Root cause
- The Agent bootstrap called `ensureEngineSession()` / `createBridgeSession()` helpers that are not defined in the current browser UI. When the active tab had no cached bridge session, bootstrap returned `null` without calling the actual session creator (`tabBridgeSession`).
- Session creation was also aborted after 2.5 seconds, too short for a cold Playwright/Chromium startup on a resource-constrained SoloHost.
- Cached session IDs could remain in the UI after a backend restart, so the Agent could try to use a stale session.

## Changes
- Agent bootstrap now calls the existing `tabBridgeSession()` directly and does not navigate to a placeholder page.
- Session-creation timeout increased from 2.5s to 20s.
- Concurrent create requests for the same tab share one in-flight promise, avoiding duplicate browser sessions.
- Existing session credentials are checked through the authenticated `/state` endpoint; stale credentials are cleared and a new session is created.
- The user-facing error now reports the underlying backend/HTTP/timeout reason and is localized in English or Vietnamese.
- Added regression assertions in `test-agent-session-recovery-v1031.js`.

## Scope / limitations
- This fix addresses the frontend bootstrap failure and stale/slow session creation. It does not claim that live Playwright/Chromium startup inside the user's deployed SoloHost container has been verified from this development environment.
- No unrelated browser features or app UI workflows were intentionally changed.
