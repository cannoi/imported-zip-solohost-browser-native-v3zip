# V10.8.0 Backend Agent Upgrade Report

## Implemented
- AI Browser Agent now runs from server-side task manager (`lib/backend-agent.js`).
- Task creation/status polling/stop/confirmation APIs are authenticated using the existing browser session token.
- The UI agent sends only task data and renders progress; it no longer reads `iframe.contentDocument` or performs DOM clicks/typing.
- Backend builds observations from the server-owned DOM snapshot, uses the existing planner, and dispatches actions through `domBridge`/WebKit worker.
- Sensitive clicks and form submissions require explicit user confirmation; password/secret fields are never filled by the agent.
- Backend action results synchronize the current browser URL and refresh the existing viewport.
- Added regression tests for server-side observation parsing and the UI/backend separation.
- Fixed normal AI Panel action dispatch to prevent repeated navigation from duplicate callbacks.
- Improved WebKit worker error logs so stderr details are useful and sensitive query values are redacted.

## Kept unchanged
- Existing UI layout, Chat/Feedback/Settings/Logs, browser tabs/history/bookmarks, SoloHost config shape, WebKit worker and proxy fallback.

## Known limitations
- WebKitGTK remains the live backend engine; it is not Chromium and cannot guarantee compatibility with every Google/YouTube/TikTok login flow, CAPTCHA, DRM or anti-bot checks.
- The user-visible viewport remains a sanitized DOM snapshot. Website JavaScript runs in the backend WebKit page, but scripts are not executed in the SoloHost-origin iframe for security. CSS and accessible DOM are projected into the viewport; highly dynamic canvas/iframe content may not fully reproduce.
- Back/forward task actions navigate through the backend agent's bounded task URL history; they do not yet share the browser shell's complete tab history.
- Docker image build and real SoloHost browser validation require a Docker-enabled deployment environment.
