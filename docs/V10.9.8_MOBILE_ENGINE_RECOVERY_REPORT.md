# SoloHost Browser v10.9.8 — Upgrade report

## Log diagnosis
- Google Search ended at `/sorry/index`: upstream Google verification/anti-abuse response, not a DOM rendering defect. Do not attempt to evade it by rotating user agents or engines.
- `Target page, context or browser has been closed`: the bridge attempted work against a dead Playwright page/context. Add preflight recovery and explicit diagnostic events.
- `m.youtube.com` was rewritten to `www.youtube.com`, and the Playwright context used a fixed desktop viewport/UA. That mismatch encouraged desktop routing and poor phone layout.
- DOM Bridge and proxy paths need separate mobile fixes because proxy HTML and sanitized engine snapshots are different rendering paths.

## Changes
- Mobile-first Playwright contexts with configurable desktop override, viewport, UA, locale, timezone and touch emulation on Chromium.
- Startup-time fallback order across installed Playwright Chromium, Firefox and WebKit engines; Chromium remains the default.
- Recovery of closed page/context/browser before navigate, content read, or event dispatch.
- Responsive viewport/CSS injected only into sanitized Bridge snapshots.
- Keep `m.youtube.com` host intact.
- Detect Google verification pages and transparently display DuckDuckGo search results for query URLs when reachable. This is a fallback, not a bypass; direct Google login remains subject to Google's security checks.

## Compatibility and scope
- UI tabs, Chat, Feedback, Settings, Logs, route structure, SoloHost package files, and existing auth/SSRF checks retained.
- `package.json` and capability version updated to 10.9.8; Docker dependencies remain Playwright 1.49.1.
- Firefox/WebKit fallback only activates if the preferred engine cannot launch. Website-specific CAPTCHA/anti-bot blocks are not resolved by engine changes.

## Validation
- JavaScript syntax checks, package/config checks, mobile regression assertions, YouTube URL normalization regression, and ZIP integrity are expected to be run before release.
- Live Google, YouTube playback, Docker/SoloHost tests require network access and a real deployment; they cannot be represented as verified by offline source tests.
