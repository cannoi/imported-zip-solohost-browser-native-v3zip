# SoloHost Browser v9.0.7 — Browser Core Upgrade Report

## Implemented
- Added a compact, responsive tab strip with new-tab, switch-tab and close-tab controls.
- Preserved the current tab list and active tab for the browser session using `sessionStorage` (up to 12 restored tabs).
- Added persistent bookmark APIs and a Bookmarks/History drawer. Users can open saved pages, remove bookmarks, and clear history.
- Added server-side storage routes under `/api/browser/{bookmarks,history}`. Existing `lib/store.js` uses JSON storage by default and optional SQLite when the `sqlite3` module is available. History remains bounded.
- Added URL/title validation for browser library writes and extended static regression checks.
- Updated the AI app knowledge/local guidance for the new controls, persistence behavior, and honest cookie/WebView limitations.
- Kept the existing Universal AI/Feedback modules, provider settings, proxy routes, themes, language toggle, reader and existing SoloHost deployment files.

## Not fully implemented / architectural limits
- This release still uses a web iframe and server-side HTML proxy; it does not embed a full Chromium engine. Some modern SPAs, banking/login sites, downloads, DRM/media, service workers and browser permissions may not work reliably in the proxy.
- Cookie management (view/edit/clear per-site cookies), true isolated browser profiles, reliable persistent authenticated sessions, extension support, native download manager, and full browser-grade history navigation are not provided by this architecture.
- For login-heavy or sensitive sites, use the external-open button. A future true-browser phase would need a supported embedded Chromium/WebView engine and a managed persistent browser profile; that is a larger runtime/security change and should not be silently added to this lightweight package.
- Runtime HTTP smoke testing could not be completed in the build sandbox because npm dependencies (including Express) are not installed there. Static tests and JavaScript syntax checks pass; the Docker image build/runtime should be checked in SoloHost before production rollout.
