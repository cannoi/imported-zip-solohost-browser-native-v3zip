# SoloHost Browser V7.6.0 — Performance upgrade report

## Baseline and scope
This release upgrades the supplied `solohost-browser-v7.5.0-security.zip`. It keeps the existing Node.js shell, native WebKitGTK engine, GTK/Xvfb, x11vnc, websockify/noVNC, AI module, navigation/security policy, media controls, downloads, and SoloHost packaging. It does not replace the browser engine or redesign the application.

## Implemented
- Added `/api/performance` and `/api/diagnostics/performance`.
- Captures Node RSS/heap and interval CPU use, cgroup-v2 memory use/limit when available, tab count, active tab, restarts, screen dimensions, and best-effort Linux `/proc` RSS/CPU for tracked WebKit/Xvfb/x11vnc/websockify process trees.
- Exposes child process IDs and display resolution through `/api/browser/status` for diagnosis.
- Enables keep-alive reuse for internal HTTP requests serving noVNC assets. The VNC/WebSocket tunnel and external website connections are unchanged.
- Adds `scripts/benchmark.js`, which repeatedly samples `/health`, `/ready`, `/api/browser/status`, and `/api/performance`, and reports p50/p95/min/max API latency plus response sizes.
- Adds a performance test and updates package version/cache-busting/documentation.
- Keeps all 48 baseline archive files; adds the benchmark script, performance monitor module, performance test, and this report. No baseline files were intentionally removed.

## What was measured in this packaging environment
- Automated JavaScript/static contract tests: passed.
- JavaScript syntax checks across project files: passed.
- ZIP integrity and file-retention check: performed when packaging.
- **No real browser performance values are claimed.** This environment does not provide the running SoloHost Docker/WebKitGTK/Xvfb stack needed to measure browser rendering, page load, FPS, media buffering, or display-transport CPU/bandwidth.

## Not implemented or not yet validated
- Adaptive memory-pressure response that changes WebKit lifecycle safely.
- True background-tab suspension/freezing. WebKitGTK does not provide a universally safe one-line switch; freezing timers can break chat notifications, real-time websites, downloads and audio playback.
- Forced lazy loading or image decode tuning. This build does not rewrite website loading semantics because it can break above-the-fold content or lazy-image implementations.
- Per-origin network connection reuse measurements, media rebuffering metrics, image decode time/memory, page navigation-to-paint, FPS/input latency, and noVNC bytes/sec/per-process CPU under load.
- Actual before/after measurements on the target SoloHost device.

## Required runtime benchmark before claiming speed/RAM improvement
1. Build and run the ZIP on SoloHost using the project's existing Docker/Compose flow.
2. Capture `node scripts/benchmark.js http://127.0.0.1:8080 30` (adjust address/port to the actual deployment).
3. Repeat with the same profile, resolution, URLs, tab count, warm-up period and idle/browse/video scenario on the previous version and V7.6.
4. Measure host/container CPU and RAM with the platform's process/container metrics, and separately record page load/paint, input responsiveness, video rebuffering and noVNC network bytes. Save raw outputs with device details.
5. Only then choose further changes to cache policy, process count, background-tab lifecycle, image decoding and display compression based on measured bottlenecks.

## Change impact
- Existing security, navigation, media, download, UI and AI behavior is intentionally preserved.
- Internal noVNC HTTP asset requests can reuse connections; this does not change the VNC WebSocket data path.
- The new performance endpoint reports diagnostics only; it does not expose a new control for website content or alter the browser's permissions.
