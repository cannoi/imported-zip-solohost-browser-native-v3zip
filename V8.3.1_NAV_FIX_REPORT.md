# V8.3.1 — Navigation / SoloHost startup fix

## Log analysis
1. Image pull OK (~388MB Playwright base).
2. Host-side SoloHost repeatedly reports missing `docker-compose.yml` under
   `C:\Users\Pi\AppData\Roaming\Pi Network\pi-apps\cannoi-solohost-browser\`
   — platform packaging path, not app crash. Compose files kept at project root + `solohost/`.
3. `SQLite unavailable, using JSON store` — optional; JSON store is intentional default (no sqlite3 dep).
4. User symptom: open URL returns to home — likely Chromium failed to launch in container
   without `--no-sandbox`, and/or HTML5 `type="url"` blocked bare domains.

## Fixes
- Chromium args: `--no-sandbox`, `--disable-setuid-sandbox` (container-safe).
- Clearer launch failure → JSON `{success:false, error:"Chromium launch failed…"}`.
- URL input `type="text"`; form does not navigate away.
- Loading keeps error/reader workspace (does not flash home).
- docker-compose ports `8080:8080` for SoloHost proxy.
- SQLite message only when SOLOHOST_DEBUG set.

## Not fixed by this package
- SoloHost host looking for compose under AppData path (Pi Network client).
