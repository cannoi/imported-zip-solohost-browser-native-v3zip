# SoloHost Browser V7.7.0 — Display Engine report

## Baseline
Upgrades `solohost-browser-v7.6.0-performance.zip` without changing the WebKit engine, security, media, AI, or SoloHost packaging model.

## Analysis
- Engine path: WebKitGTK + Node shell (correct for SoloHost).
- Display path still: Xvfb → x11vnc → websockify → noVNC.
- Hard limit: UI runs in Pi Browser; native surface cannot embed in that DOM.
- Replacing noVNC with WebRTC/Selkies without measurement risks larger images and proxy/TURN failures.

## Implemented
1. `lib/display-manager.js` — single place for display mode and RFB tuning.
2. Engine manager uses display-manager for x11vnc/websockify args.
3. Bandwidth-oriented defaults: FPS 12, wait/defer 25ms, ncache 8, speeds=dsl.
4. `GET /api/display/status`.
5. Architecture + changelog notes.

## Intentionally not done
- Full removal of noVNC (no SoloHost benchmark proof).
- WebRTC/Selkies default (image size / ICE risk).
- Native offscreen capture stream (needs new native code path).
- Claims of lower latency/CPU without device measurement.

## How to tune on SoloHost
```text
SOLOHOST_DISPLAY_FPS=10
SOLOHOST_DISPLAY_SPEEDS=modem
SOLOHOST_DISPLAY_NCACHE=10
SOLOHOST_DISPLAY_MODE=novnc
```

Measure with existing `scripts/benchmark.js` and host metrics before changing the transport family.
